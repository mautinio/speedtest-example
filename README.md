# Speedtest — замер скорости скачивания

Консольный скрипт на Node.js и TypeScript. Делает **10 последовательных** GET-запросов к указанному адресу, дожидается полного ответа на каждый, считает среднее время запроса и общий объём данных и печатает скорость скачивания.

## Быстрый старт

Нужен Node.js **20 или новее** (проверено на 24).

```bash
npm install
```

```bash
npm start -- https://speed.cloudflare.com/__down?bytes=10000000
```

Аргумент один — адрес `http://` или `https://`. Лучше брать файл от нескольких мегабайт (см. [Ограничения](#ограничения)).

## Пример вывода

```
Цель: https://speed.cloudflare.com/__down?bytes=5000000
Запросов: 10 (последовательно)

# 1:    751 мс, 4.77 МБ, 88.93 Мбит/с
# 2:    659 мс, 4.77 МБ, 88.19 Мбит/с
...
#10:    438 мс, 4.77 МБ, 121.51 Мбит/с

--- Итоги ---
Среднее время запроса: 506 мс
Всего скачано:         47.68 МБ (50000000 байт)
Общее время запросов:  5.06 с
Из них передача тела:  3.77 с
Скорость скачивания:   106.08 Мбит/с (12.65 МБ/с)
```

Если адрес не передан или некорректен, скрипт печатает подсказку. Если запрос завершился ошибкой (сеть, статус не 2xx), печатает её. В обоих случаях код выхода — 1.

## Единицы измерения

| Величина | Единица | Как считается |
|---|---|---|
| Время запроса | миллисекунды (мс) | от отправки запроса до последнего байта тела |
| Объём данных | МБ (1 МБ = 1 048 576 байт) и байты | сумма длин полученных чанков |
| Скорость | **Мбит/с** (1 Мбит = 1 000 000 бит) | `байты × 8 / 1 000 000 / секунды передачи тела` |
| Скорость | МБ/с | `байты / 1 048 576 / секунды передачи тела` |

Основная единица — Мбит/с: в ней скорость канала указывают провайдеры.

## Как считается скорость

Время запроса и скорость измеряются по разным отрезкам:

- **Время запроса** — полное: включает DNS, установку соединения и ожидание ответа сервера. Это то, сколько ждал бы пользователь.
- **Скорость** — общий объём, делённый на суммарное **время передачи тела** (от получения заголовков ответа до последнего байта). Пока сервер не начал отвечать, данные не идут; это время говорит о задержке, а не о пропускной способности канала, поэтому в скорость не входит.

Запрос отправляется с заголовком `Accept-Encoding: identity`, чтобы сервер не сжимал ответ. Иначе `fetch` распаковал бы тело сам, и посчитанный объём оказался бы больше реально переданного по сети.

Время берётся из `performance.now()` — монотонных часов, на которые не влияет перевод системного времени.

## Структура проекта

```
src/
├── index.ts            точка входа: проверка адреса, сборка объектов, код выхода
├── SpeedTest.ts        сценарий: N запросов строго по очереди → SpeedReport
├── Downloader.ts       интерфейс Downloader и его реализация HttpDownloader на fetch
├── DownloadSample.ts   один замер: байты, время запроса, время передачи тела
├── SpeedReport.ts      итоги по всем замерам: суммы, среднее время, скорость
├── ConsoleReporter.ts  вывод в консоль и пересчёт в мс, МБ, Мбит/с
└── Messages.ts         все тексты и названия единиц; каждая фраза — функция
test/
├── SpeedTest.test.ts       число и последовательность запросов, итоговые расчёты
└── HttpDownloader.test.ts  подсчёт байт, время передачи, заголовок, ошибки
```

Структура плоская: у скрипта один сценарий, и отдельные слои дали бы только обёртки. Деление идёт по причинам для изменения:

- **Как качать** — `Downloader.ts`. `SpeedTest` зависит от интерфейса `Downloader`, а не от `fetch`, поэтому тестируется с поддельным загрузчиком без сети. Это единственная абстракция в проекте.
- **Как считать** — `DownloadSample.ts` и `SpeedReport.ts`. Хранят только байты и миллисекунды, про сеть и консоль не знают.
- **Как показывать** — `ConsoleReporter.ts` и `Messages.ts`. Чтобы поменять формулировку, достаточно открыть `Messages.ts`.
- **Как запускать** — `index.ts`. Единственное место, где создаются конкретные объекты.

Зависимости только для разработки: `typescript` (проверка типов), `tsx` (запуск `.ts` без отдельной сборки) и `@types/node`. В рантайме используются встроенные `fetch` и `node:test`.

## Ограничения

- **Нужен большой файл.** Маленький ответ приходит почти целиком вместе с заголовками, время передачи тела получается близким к нулю, и скорость теряет смысл. На коротких передачах к тому же TCP не успевает разогнаться.
- **Сервер может проигнорировать `Accept-Encoding: identity`** и всё равно сжать ответ; тогда объём будет завышен.
- **Измеряется одно соединение.** Запросы идут по одному, поэтому результат — скорость одного потока, а не суммарная пропускная способность канала.
- **Первые запросы медленнее.** На них приходятся DNS и установка TLS-соединения; это видно по времени запроса, но на скорость не влияет.
